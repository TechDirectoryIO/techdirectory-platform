## Go-live (change window, Tuesday to Thursday 07:00–09:00, after PR #1 is merged)

1. **Owner, before the window (5 minutes):** sign in at dash.cloudflare.com and say whether techdirectory.io is in your account. If it is, I switch off Cloudflare's **managed robots.txt** setting (the "Manage your robots.txt" option in its bot settings) so the site serves one file. If it isn't, the platform controls Cloudflare. I then ask platform support to switch it off, and use the fallback below until they do.
2. Back up the current robots.txt from cPanel File Manager (`public_html/robots.txt`). It is also saved in `docs/baseline/`.
3. Upload `site/seo/robots.txt`. Check it from outside: the live file must match the repository copy, and a fetch as GPTBot must be refused on a listing and allowed on a guide.
4. Create the IndexNow key (32 random characters), upload `<key>.txt` holding the key to the site root, and save the key in Make as a variable. Send one ping for the homepage and check that the response is 200 or 202.
5. Search Console: robots.txt report shows the new file fetched with no errors.
6. Rollback: put the backup file back (under a minute).

**Fallback if Cloudflare's block can't be switched off yet:** upload the same file without its `User-agent: *` group, because Cloudflare already adds one. Parsers that follow Google's rules merge the two halves, so training bots get the guides. Bots that read only the first group stay blocked from everything, which is safe. **The gap in the fallback:** Cloudflare's own `*` group says `Allow: /`, so unnamed bots keep reaching listings until Cloudflare's block is switched off. That is why step 1 matters for the data products.

## IndexNow pings in Make (35.3)

| Trigger | URLs sent |
| --- | --- |
| Listing created, changed, claimed or closed | The listing's URL |
| Guide, announcement or sponsored post published or updated | The post's URL (B46 publish step adds this) |

- **Make:** one scenario runs every hour. It reads the listings and posts changed since the last run from the TD API and gathers the URLs into one array. It sends `POST https://api.indexnow.org/indexnow` with the body built in `indexnow.py`, up to 10,000 URLs a request, and skips the request when there are no URLs.
- **To confirm in the window:** whether the TD API can filter members by last-changed date. If not, the scenario uses the platform's "member updated" webhook.
- **Make's free plan allows 2 scenarios.** This one and B46's order flow need 3 between them. The B46 decision (Cloudflare Worker or Make Core) settles this too: a Worker can also run the hourly ping at no cost.
- **Acceptance test:** change a test listing; within the hour, Make's history shows a 200 or 202 for its URL.

## How this protects the data products (36.9)

robots.txt is a request, not a lock. It keeps out well-behaved bulk crawlers. The rest is done by:

- **Cloudflare (26.4):** bot fight mode, the 60-page-views-a-minute limit on listing and results pages, and blocking of known scrapers. Bots claiming to be Googlebot or Bingbot are checked against their real addresses.
- **What is sold isn't on public pages:** the change feed, signal history and alerts, List check matching, bulk export and the demand figures (quote requests, budgets, prices) live only behind paid API keys and logins.
- **Search and AI answer bots read one page at a time to answer a question and link back.** That is the AI visibility members pay for (section 35), not a copy of the database.
